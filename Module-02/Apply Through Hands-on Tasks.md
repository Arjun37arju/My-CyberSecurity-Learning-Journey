## a. Analyze Malware Samples Safely

### Task

Practice basic **malware analysis in an isolated security lab**.

Use a controlled virtual machine and analyze a safe malware sample or a publicly available malware-analysis dataset.

### What to Do

Research and document:

* Malware name
* Malware type
* File information
* General behavior
* Files or processes involved
* Network activity, if documented
* Potential impact
* Detection methods
* Mitigation methods

```text
Malware Sample
      ↓
Isolated Lab
      ↓
Observe Behavior
      ↓
Collect Findings
      ↓
Analyze
      ↓
Document
```

### Deliverable

Create a **Malware Analysis Report** containing:

```text
Malware:
Type:
Analysis Environment:
Observed Behavior:
Indicators:
Potential Impact:
Detection:
Mitigation:
Sources:
```

### Safety

* Use an isolated VM.
* Do not use your personal/production system.
* Do not connect unknown malware to the open Internet.
* Take a VM snapshot before testing.
* Use only samples you are authorized to analyze.

**Goal:**

> Learn how malware behavior can be safely observed and documented in a controlled environment.

## b. Research Recent CVEs

### Task

Research **recently published cybersecurity vulnerabilities** using trusted vulnerability databases and vendor advisories.

Choose **3–5 CVEs**.

### What to Do

For each CVE, research:

* CVE ID
* Vulnerability description
* Affected software
* Affected versions
* CVSS severity
* Potential impact
* Exploit availability, if publicly documented
* Available patch or mitigation

```text
CVE
 ↓
Understand Vulnerability
 ↓
Check Severity
 ↓
Identify Affected Software
 ↓
Research Fix
 ↓
Document
```

### Deliverable

Create a **CVE Research Report**:

| CVE | Software | Severity | Impact | Fix / Mitigation |
| --- | -------- | -------- | ------ | ---------------- |
|     |          |          |        |                  |
|     |          |          |        |                  |
|     |          |          |        |                  |

Then choose **one CVE** and perform a deeper analysis.

**Goal:**

> Develop the ability to research current vulnerabilities and understand their security impact.

## c. Perform OSINT Investigations

### Task

Perform an **authorized OSINT investigation** using only publicly available information.

Choose a safe research target such as:

* A cybersecurity incident
* A malware campaign
* A publicly disclosed vulnerability
* A fictional organization
* Your own organization/project

### What to Do

Follow this workflow:

```text
Research Question
      ↓
Collect Public Information
      ↓
Search Multiple Sources
      ↓
Verify Information
      ↓
Connect Findings
      ↓
Document Evidence
```

Research information such as:

* Public websites
* Public reports
* Security advisories
* Public incident information
* Technologies
* Publicly available documents

### Deliverable

Create an **OSINT Investigation Report**:

```text
Research Question:

Scope:

Sources:

Information Collected:

Verified Findings:

Analysis:

Conclusion:

Sources:
```

**Goal:**

> Practice collecting, verifying, and analyzing publicly available information.

## d. Document Attack Techniques

### Task

Possible topics:

* Phishing
* Social engineering
* Credential attacks
* Malware delivery
* Denial of Service
* Reconnaissance

### What to Do

For each technique, document:

* Definition
* General attack flow
* Target
* Attacker objective

```text
      ↓
Impact
      ↓
Detection
      ↓
Defense
```

## e. Create Vulnerability Reports

### Task

Create professional vulnerability reports based on **authorized security testing or publicly documented vulnerabilities**.

For practice, you can use:

* Your own lab
* Intentionally vulnerable applications
* Training platforms
* Public CVE information

### What to Do

Document:

* Vulnerability title
* Description
* Affected asset
* Vulnerability type
* Severity
* Evidence
* Potential impact
* Recommended remediation
* Verification method

```text
Vulnerability
      ↓
Identify
      ↓
Collect Evidence
      ↓
Assess Severity
      ↓
Explain Impact
      ↓
Recommend Fix
      ↓
Verify Remediation
```

### Deliverable

Create a **Professional Vulnerability Report**:

```text
Title:

Severity:

Affected Asset:

Description:

Vulnerability Type:

Evidence:

Impact:

Recommendation:
```

### Goal

> Learn how security professionals document vulnerabilities clearly so that technical teams can understand and fix them.
