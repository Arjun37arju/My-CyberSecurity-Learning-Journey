## Introduction

**Log analysis** is the process of collecting, reading, filtering, and investigating log entries to understand what happened on a system.

Logs contain important information such as:

* Date and time
* Username
* Source IP address
* System events
* Login attempts
* Service activity
* Errors and warnings
* Security-related events

In cybersecurity, log analysis is important for detecting **unauthorized access, brute-force attacks, malware activity, privilege abuse, and other suspicious behavior**.

---

## a. System Logs

**System logs** record events generated by the operating system. They help administrators and security analysts understand what is happening inside the system.

### Common System Log Locations

On Kali Linux/Debian-based systems:

```bash
/var/log/syslog
/var/log/kern.log
/var/log/messages
```

Modern Linux systems also commonly use the **systemd journal**.

### Important Commands

```bash
journalctl
journalctl -n 20
journalctl -f
journalctl -p err
dmesg
```

### Examples

```bash
sudo journalctl
```

Displays system journal logs.

```bash
sudo journalctl -n 20
```

Displays the latest 20 log entries.

```bash
sudo journalctl -f
```

Continuously displays new log entries as they are generated.

```bash
sudo journalctl -p err
```

Displays error-level events.

```bash
dmesg
```

Displays kernel-related messages.

### What to Observe

* System errors
* Kernel messages
* Hardware-related events
* System startup/shutdown
* Process-related events
* Unexpected system behavior

### Cybersecurity Relevance

System logs can help identify:

* System failures
* Suspicious activity
* Unexpected processes
* Kernel-level problems
* Potential system compromise

## b. Authentication Logs

**Authentication logs** record activities related to users accessing the system.

They can contain:

* Successful logins
* Failed login attempts
* SSH connections
* `sudo` usage
* User authentication
* Account-related events

On Kali Linux/Debian:

```bash
/var/log/auth.log
```

### Important Commands

```bash
sudo cat /var/log/auth.log
sudo grep "Failed password" /var/log/auth.log
sudo grep "Accepted" /var/log/auth.log
sudo grep "sudo" /var/log/auth.log
```

### Examples

```bash
sudo grep "Failed password" /var/log/auth.log
```

Finds failed authentication attempts.

```bash
sudo grep "Accepted" /var/log/auth.log
```

Finds successful SSH authentication attempts.

```bash
sudo grep "sudo" /var/log/auth.log
```

Finds `sudo`-related activities.

### Example Log

```text
Aug 21 10:15:22 kali sshd[1234]: Failed password for user from 192.168.1.10
```

Important information:

```text
Time       → 10:15:22
Service    → sshd
Event      → Failed password
User       → user
Source IP  → 192.168.1.10
```

### What to Observe

* Repeated failed logins
* Successful login after many failures
* Unknown usernames
* Unusual login times
* Unknown source IP addresses
* Unexpected `sudo` activity

### Cybersecurity Relevance

Authentication logs help detect:

* Brute-force attacks
* Password attacks
* Account compromise
* Unauthorized SSH access
* Privilege abuse

## c. Service Logs

**Service logs** record activities generated by applications and background services.

Examples:

* Apache
* Nginx
* SSH
* MySQL
* DNS
* Firewall services

### Apache Example

Apache commonly stores logs in:

```bash
/var/log/apache2/
```

Important files:

```bash
access.log
error.log
```

### Important Commands

```bash
sudo cat /var/log/apache2/access.log
sudo cat /var/log/apache2/error.log
sudo grep "404" /var/log/apache2/access.log
sudo grep "500" /var/log/apache2/access.log
```

### Example

```bash
sudo grep "404" /var/log/apache2/access.log
```

Finds HTTP 404 responses.

```bash
sudo grep "500" /var/log/apache2/access.log
```

Finds HTTP 500 server errors.

### What to Observe

* Source IP
* Requested URL
* HTTP method
* HTTP status code
* Request frequency
* User-Agent
* Error messages

### Cybersecurity Relevance

Service logs can help identify:

* Web scanning
* Directory enumeration
* Suspicious requests
* Application attacks
* Server errors
* Possible exploitation attempts

## d. Log Investigation

**Log investigation** means examining log entries to determine **what happened, when it happened, where it came from, and whether it was malicious**.

### Step 1: Find Failed Login Attempts

```bash
sudo grep "Failed password" /var/log/auth.log
```

### Step 2: Find Successful Logins

```bash
sudo grep "Accepted" /var/log/auth.log
```

### Step 3: Identify Source IP Addresses

```bash
sudo grep "Failed password" /var/log/auth.log
```

Look for the IP address in each entry.

### Step 4: Count Repeated Attempts

```bash
sudo grep "Failed password" /var/log/auth.log | sort | uniq -c
```

This helps identify repeated authentication attempts.

### Step 5: Check the Timeline

Build a timeline:

```text
Failed Login
     ↓
Repeated Failed Logins
     ↓
Successful Login
     ↓
Sudo Activity
     ↓
Suspicious Command
```

### Step 6: Correlate Different Logs

Don't investigate only one log.

For example:

```text
Authentication Log
        ↓
Successful SSH Login
        ↓
System Log
        ↓
New Process Started
        ↓
Service Log
        ↓
Suspicious Request
```

This gives a better understanding of the incident.

### What to Look For

* Who performed the action?
* When did it happen?
* What IP address was involved?
* What service was accessed?
* Was the activity successful?
* Did suspicious activity happen afterward?

### Cybersecurity Relevance

Log investigation is an important SOC skill because analysts use logs to:

* Detect incidents
* Investigate attacks
* Build timelines
* Identify compromised accounts
* Collect evidence
* Understand attacker activity

## e. Security Indicators

**Security indicators** are suspicious patterns or events that may indicate an attack or security incident.

### 1. Multiple Failed Logins

```bash
sudo grep "Failed password" /var/log/auth.log
```

**Possible indicator:**

```text
Brute-force attack
```

---

### 2. Successful Login After Many Failures

```bash
sudo grep "Accepted" /var/log/auth.log
```

**Possible indicator:**

```text
Account compromise
```

---

### 3. Unusual Source IP

Check the IP associated with authentication events.

```bash
sudo grep "Failed password" /var/log/auth.log
```

**Possible indicator:**

```text
Unauthorized access attempt
```

---

### 4. Repeated 404 Requests

```bash
sudo grep "404" /var/log/apache2/access.log
```

**Possible indicator:**

```text
Web scanning / directory enumeration
```

---

### 5. Unexpected Sudo Activity

```bash
sudo grep "sudo" /var/log/auth.log
```

**Possible indicator:**

```text
Privilege abuse
```

---

### 6. Suspicious Process Activity

```bash
ps aux
```

Look for:

* Unknown processes
* Unusual process names
* High CPU usage
* Processes running as `root`

**Possible indicator:**

```text
Malware or unauthorized process
```

   System Logs          Authentication Logs
        ↓                     ↓
   Service Logs        Successful/Failed Login

                   ↓
          Find Security Indicators
                   ↓

## Conclusion

Log analysis is a fundamental cybersecurity skill. A security analyst should be able to **read logs, filter important events, identify suspicious indicators, correlate different logs, and build an incident timeline**.

The basic flow to remember is:

```text
Collect Logs
     ↓
Read Logs
     ↓
Filter Events
     ↓
Investigate
     ↓
Find Indicators
     ↓
Build Timeline
     ↓
Identify Incident
```
